# Codex CLI / deepseek-flash：L10–L12 三次复测（2026-10-29）

- 被测：Codex CLI 0.163.0，provider `custom`（DeepSeek），模型 `deepseek-flash`
- 环境：Linux，Python 3 / Node 22.22.3，Codex 以 `codex exec --json` 非交互运行
- 方法：L10 / L11 / L12 各 3 次，每次独立 fixture 副本；`max_rounds=1`（只看第一轮）
- 判分：隐藏验收在 agent 上下文之外；`grade.py` 同时检查可见测试、禁区、干净克隆
- 产物：`runs/2026-10-29-codex-L10-L12/`

## 结果

| 任务 | 档 | 通过 | 耗时 | 需求 | 隐藏验收 | 干净克隆 | 改动 |
|---|---|---|---|---|---|---|---|
| `L10-stock-reserve` | L10 并发服务 | 3/3 | 103.5 / 149.8 / 128.2s | 6/6 | 7/7 | 3/3 | +84…+110 / −17…−18 |
| `L11-report-throughput` | L11 性能预算 | 3/3 | 86.5 / 83.0 / 108.0s | 4/4 | 4/4 | 3/3 | +32…+37 / −7…−15 |
| `L12-async-queue` | L12 Node 异步 | 3/3 | 41.1 / 37.8 / 48.1s | 6/6 | 8/8 | 3/3 | +41…+54 / −7 |

**9/9 通过，全部第 1 轮，全部 `usable=true`。** 没有 `scope_violation`、没有残留调试文件、没有未声明依赖。

## 成本

| 任务 | 平均耗时 | 平均输入 token | 平均输出 token | 平均总 token |
|---|---|---|---|---|
| L10 | 127.2s | 645,833 | 22,023 | 667,856 |
| L11 | 92.5s | 417,115 | 14,459 | 431,574 |
| L12 | 42.3s | 150,373 | 6,733 | 157,106 |

L10 是最贵的：并发/幂等/落盘三件事必须一起改，模型花了更多轮工具调用和自检。
L11 虽然要重构 O(n²)，但模式明确（按币种建索引 + 二分），成本居中。
L12 最便宜：标准 worker pool + 重试，模型很熟。

## 结论

1. **三条新难度轴没有拉开差距。** L10 服务并发、L11 性能预算、L12 Node 异步，
   对这个配置下的 Codex 都是第 1 轮通过。TRAE 旁证也只跑了 L10 / L12 各 1 次，
   都通过；重复跑受 TRAE 会话上下文复用影响，未计入统计。
2. **成本仍然是唯一稳定信号。** 通过率全 100% 时，token 和耗时还能区分任务重量，
   但区分不了工具强弱。
3. **L11 的 3 秒预算不构成瓶颈。** 参考解约 0.1s，模型直接换索引；如果要把性能变成
   真正的轴，预算要压到接近实现极限（例如 0.5s），或加入内存/流式约束。
4. **L12 证明多语言 runner 可用，但题目本身是教科书模式。** 要拦人，得换成事件循环
   饥饿、取消传播、背压、AbortSignal 这类边界，而不是再加一个 worker pool。

## 旁证：TRAE CN 3.6.4

- L10 1/1 通过（53.5s）；L12 1/1 通过（33.6s）。
- L12 第 3 次复跑时，TRAE 会复用上一轮会话上下文，认为「工作区已改好」，实际文件没动；
  判分判 `visible_tests_failed`。这是驱动器的会话隔离问题，不是能力结论。
- 驱动器本次修了两处：CDP 页面从 `solo-lite` 改为 `workbench`（3.6.4 的页面 URL），
  授权标签补上工作区信任弹窗（`是，我信任此作者` / `信任文件夹并启用所有功能`）。

## 建议

- 停止继续加同形状的题；通过率已经饱和。
- 下一批要测的是「目标定义」而不是「代码实现」：同一仓库给一个模糊目标，要求先写
  rubric / 计划，再实现，再自证；判分看计划与结果的对应关系，而不是只看测试。
- 或者把「独立评审意见数 / 返工轮次 / token 成本」纳入记分卡，作为通过率之外的分层。
